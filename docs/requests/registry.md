# Registre des demandes durables SeenIt

| ID | Date | Décision durable | Exigences / trace | Statut |
|---|---|---|---|---|
| USR-2026-08-30-001 | 2026-08-30 | SeenIt doit rester fonctionnel en PWA et surtout dans l'APK, avec des adaptations natives explicites comme l'ouverture de Plex Android. | `SEENIT-PLATFORM-001`, `SEENIT-APK-001`, `SEENIT-APK-002` | active |
| USR-2026-08-30-002 | 2026-08-30 | L'identité Plex/TMDB n'est jamais devinée depuis le titre ou l'année ; seuls des identifiants techniques vérifiés sont acceptés. | `SEENIT-IDENTITY-001`, `SEENIT-PLEX-001` | active |
| USR-2026-08-30-003 | 2026-08-30 | Les données d'un même compte SeenIt sont partagées entre PWA et APK, tandis que les secrets, caches et notifications restent isolés par UID et, lorsque nécessaire, par appareil. | `SEENIT-DATA-001`, `SEENIT-DATA-003`, `SEENIT-NOTIFICATION-001` | active |
| USR-2026-08-31-001 | 2026-08-31 | Toute évolution comportementale passe par une SPEC à jour et des tests automatisés afin de réduire les régressions. | `SEENIT-QUALITY-001` | active |
| USR-2026-08-31-002 | 2026-08-31 | L'APK reste installable par-dessus la version précédente ; son icône, son identité, sa signature et ses comportements natifs ne changent jamais accidentellement. | `SEENIT-APK-001`, `SEENIT-APK-002`, `SEENIT-APK-003`, [issue #9](https://github.com/julfou7/seenit-app/issues/9), [issue #13](https://github.com/julfou7/seenit-app/issues/13) | active |
| USR-2026-08-31-003 | 2026-08-31 | Chaque audit est enregistré et produit des issues GitHub priorisées ; chaque nouvelle demande durable absente de la SPEC est mémorisée, spécifiée et testée. | `SEENIT-QUALITY-002`, `SEENIT-QUALITY-003`, [audit global](../audits/audit-global-2026-08-31.md) | active |
| USR-2026-09-01-001 | 2026-09-01 | Une issue en cours doit rester à jour pendant toute l'intervention : état, preuves, commits/runs et blocages sont actualisés au fil des jalons, et chaque checkbox d'acceptation est cochée dès que son critère est réellement prouvé. | `SEENIT-QUALITY-004` | active |
| USR-2026-09-01-002 | 2026-09-01 | Les imports/synchronisations AI Studio ne doivent jamais réécrire silencieusement la base Firestore, l'identité Firebase Android ou les fichiers canoniques du dépôt ; GitHub reste autoritatif et les invariants sont protégés par des tests. | `SEENIT-DATA-005`, `SEENIT-APK-004`, `SEENIT-QUALITY-005`, [issue #21](https://github.com/julfou7/seenit-app/issues/21) | active |
| USR-2026-09-01-003 | 2026-09-01 | Les changements mineurs et sûrs, comme un renommage de label, suivent un parcours de validation et de déploiement light ; tout risque ou doute conserve automatiquement le pipeline APK complet. | `SEENIT-QUALITY-006` | active |
| USR-2026-09-01-004 | 2026-09-01 | La base Firestore canonique `default` doit rester protégée contre sa suppression accidentelle et le dépôt SeenIt ne doit plus conserver de `firestoreDatabaseId` AI Studio historique susceptible de recréer une base parasite. | `SEENIT-DATA-005`, `SEENIT-DATA-006`, [issue #22](https://github.com/julfou7/seenit-app/issues/22) | active |
| USR-2026-09-02-001 | 2026-09-02 | La synchronisation du code SeenIt entre AI Studio et GitHub repose désormais uniquement sur l’intégration native AI Studio ; le pull Git embarqué dans l’application et le backend est supprimé. | `SEENIT-QUALITY-007`, [issue #33](https://github.com/julfou7/seenit-app/issues/33) | active |
| USR-2026-09-02-002 | 2026-09-02 | Les previews AI Studio `ais-dev-*` utilisent le backend canonique `seenit.ai.studio` comme l'APK ; une réponse HTML 200 n'est jamais un succès API et les rejets asynchrones backend restent contenus. | `SEENIT-PLATFORM-001`, `SEENIT-RUNTIME-001`, [issue #28](https://github.com/julfou7/seenit-app/issues/28) | active |
